# Data dictionary (selected fields)

## Stage files

### `data_stage/bonds_panel_postcode.parquet`
- `postcode` – 4-digit postcode (string)
- `month` – month start (pandas Timestamp)
- `median_rent` – median weekly rent from lodgements
- `p90_rent` – 90th percentile weekly rent
- `count_lodgements` – number of lodgements (new tenancies)
- `mean_days_held` – mean days a tenancy was held (from disposals)
- `count_disposals` – number of disposals/refunds (ended tenancies)
- `stock_bonds` – stock of active rental bonds
- `churn_rate` – (lodgements + disposals) / stock
- `net_stock_change` – lodgements - disposals
- `rent_momentum` – pct change in median rent vs previous month

### `data_stage/bonds_panel_sa2.parquet`
- `sa2_code` – SA2 code (string)
- `month` – month start
- Aggregated counterparts of the postcode panel, weighted via POA→SA2 allocation ratios.

### `data_stage/availability_nowcast_sa2.parquet`
- `sa2_code`, `month`, `availability_rate` – posterior mean of availability per stock.

### `data_stage/price_pressure_forecast_sa2.parquet`
- `sa2_code`, `month`, `price_pressure_prob` – posterior mean probability that next month’s median rent growth exceeds the configured threshold.

### `data_stage/house_prices_sa2_monthly.parquet`
- `sa2_code`, `month`, `median_house_price` – suburb-weighted median sale price carried forward to each SA2 for the given month.
- `price_allocation_weight_sum` – sum of SAL→SA2 allocation ratios contributing to the weighted price (≈1 when fully covered).
- `price_suburb_count` – number of contributing suburbs in that SA2 for the month.
- Only suburbs with 2021 SAL population ≥ 5,000 contribute to these aggregates.

### Forecast evaluation files (generated by `make fit_latest`)
- `outputs/evaluations/forecast_eval_summary.csv` – month-by-month accuracy for the walk-forward run using the feature-rich configuration (recency half-life 6, external/calendar/spatial features, relaxed priors).
  - Key columns:
    - `precision_at_10`, `precision_at_20`, `precision_at_50` – hit rate among the top K SA2s each month.
    - `lift_at_K` – precision divided by the month’s base rate (values > 1 show improvement over picking at random).
    - `auc`, `brier` – discrimination/calibration metrics per month.
  - Current averages (Mar–Aug 2025): precision@10≈0.80, lift@10≈2.35×, precision@20≈0.76, lift@20≈2.22×, precision@50≈0.66, lift@50≈1.87×, mean AUC≈0.71, mean Brier≈0.21.
- `outputs/evaluations/forecast_posterior_summary_dynamic.csv` – posterior diagnostics for the latest fit (hierarchy includes relaxed SA2 priors and month-level random effects).

### Forecast history
- `data_stage/price_pressure_forecast_sa2_history.parquet` – combined walk-forward predictions (Mar–Sep 2025) for the canonical 2 % rent-rise definition. Probability mass is no longer saturated; e.g. only 2–20 % of SA2s exceed 0.5 per month at the latest run.
- `data_stage/price_pressure_forecast_sa2_history_thr0p010.parquet`, `…_thr0p020.parquet`, `…_thr0p030.parquet` – aligned history exports for the 1 %, 2 %, and 3 % rent-jump definitions produced by the multi-threshold validation script. (Fallback filenames without the trailing zero exist for backwards compatibility.)

## Site JSON (docs/data)

These files power the interactive map in `docs/index.html`:

- `docs/data/thresholds.json` – metadata for the available rent-rise definitions (id, label, event threshold, default flag).
- `docs/data/<threshold_id>/months.json` – array of available forecast months as `YYYY-MM` for that threshold (e.g. `thr0p020` for ≥ 2 %).
- `docs/data/<threshold_id>/YYYY-MM.json` – per-month objects keyed by `sa2_code` with:
  - `p` – forecast probability (Pr[Δrent > threshold]).
  - `l`, `u` – lower/upper bounds of the 90 % credible interval (≈ p05, p95) when available.
  - `y` – realized outcome for that month (1 if Δrent > threshold, else 0; may be null if not yet realized).
  - `pred`, `correct`, `cls` – classification metadata evaluated at the per-month best‑F1 cutoff.
- `docs/data/<threshold_id>/summary.json` – per‑month evaluation metrics for the selected threshold (includes `precision_at_0_5`, `recall_at_0_5`, `accuracy_at_0_5`, plus the best-F1 threshold metrics).
- For convenience, the default threshold (currently 2 %) is also copied to the legacy locations `docs/data/months.json`, `docs/data/YYYY-MM.json`, and `docs/data/summary.json` so existing embeds continue to work.

UI note: the “Model correctness” view now uses the per-month best-F1 probability cutoff surfaced in the evaluation summary, not a fixed 0.60 threshold.
